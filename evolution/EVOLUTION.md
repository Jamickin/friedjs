# How FriedJS evolves

Every change to FriedJS goes around one loop, and leaves an entry here.

1. **Friction.** An AI session or person using FriedJS hits something in the way. They append a line to `evolution/friction.jsonl` (format in `evolution/README.md`).
2. **Digest.** Repeated or serious friction is grouped by op and goal into one concrete problem, with the lines that prove it.
3. **Plan.** A change is proposed against that evidence: additive by default. Changing or removing behaviour needs a deprecation entry in `docs/known-limitations.md` and a migration patch for every consumer.
4. **Gates.** It ships only when all pass: `npm test` (including `tests/docs-truth.test.js`), `node stress.js` and `node benchmark.js` within 25% of `evolution/baseline.md`, every consumer's tests, this entry, and a verification note in `docs/MERGE.md`.
5. **Sync.** The pinned FriedJS is copied into each consumer (`fried sync <consumer>`), its version recorded, its tests run, and rolled back on failure.
6. Evidence over taste: an entry without friction evidence is not a reason to change anything.

## Entry format

```
## <id>. <title>
- id: <number, never reused>
- date: <YYYY-MM-DD>
- friction evidence: <friction.jsonl lines, or the defect found, with exact paths/errors>
- change: <what changed, files touched>
- tests: <tests added or changed>
- gates run: <each gate and its result, numbers vs baseline.md>
- consumers migrated: <each consumer and how, or "none needed: no behaviour change">
```

## 3. fried-router matches :param routes and a query string (phase F3a)
- id: 3
- date: 2026-10-22
- friction evidence: `evolution/friction.jsonl` line 1 (consumer `orchestra-dashboard`, agent `codex`, op `route matching`): want "Match parameter routes such as /musicians/:id and /plans/:id", tried "Used fried-router router() route table", error "fried-router matches exact paths only", workaround "Use its currentRoute and navigate state, with route pattern compilation/matching in dashboard/lib/routes.js". That workaround is 3,566 bytes / 85 lines in the Orchestra repo, of which about 45 lines (`compile`, `buildTable`'s specificity sort, `parseQuery`, `match` with decoding and fallback) re-implement routing; the rest is the dashboard's tab table and keyboard shortcuts. Entry 2 named this line as the first candidate for a change.
- change: `addons/fried-router.js` only (plus the version stamp). `router(routes)` resolves through the new `matchRoute(routes, path)`: (1) a key equal to the whole path, query included, exactly as before; (2) the key equal to the path without its query; (3) `:name` patterns compared segment by segment (no regex built from pattern text), most literal segments wins, ties by declaration order, trailing slash ignored, params URL-decoded and kept raw on a bad escape; (4) `"*"`. The view is called with one argument `{ params, query, path }` (views with no parameters are unaffected). New export `parseRoute(path)` -> `{ path, query }` (decoded, `+` is a space, first value wins, own-property writes so `__proto__` is just a key). `navigate` is unchanged and already accepted a query string. Behaviour difference, documented: a path that used to fall to `"*"` only because of a query string or a trailing slash now reaches its route. Version 0.3.0 (`fried.js` `VERSION`, `package.json`, `CHANGELOG.md`, which also ships the F2 tooling that was under Unreleased). Docs: `docs/framework-api.md` (router section, both exports, example), `docs/known-limitations.md` (entry marked FIXED in 0.3.0), the router lines in `CLAUDE.md` and `README.md`, the 0.3.0 note in `docs/MERGE.md`.
- tests: `tests/router-params.test.js` (11, with a 4-line `window` shim): exact routes and `"*"` unchanged, a no-argument view, an exact key containing `?`, params and query via `router`, `navigate` with a query, `parseRoute` (repeats, bare flags, `%2F`, bad `%`, `__proto__`), param decoding (`%2F`, bad escape, UTF-8), empty segment and segment-count mismatch -> `null`, the result shape, specificity and ties, trailing slashes, `"*"` last with its query, regex metacharacters in a pattern matched literally, and 60 hostile/long-path matches (50,000 segments, 200,000 `%`) under 2 s (about 60 ms here).
- gates run (all with `FRIED_FRICTION_LOG` unset; see the note below): `npm test` 62 pass, 0 fail (51 before + 11), docs-truth green. `node stress.js` x3: 43/43 each; create 10,000 rows median 4.07 ms (runs 4.04, 4.07, 5.23; baseline 4.3, -5%), append 1,000 median 2.10 ms (2.16, 1.84, 2.10; 2.2, -5%). `node benchmark.js` x3, medians vs baseline: 1,000 cards 2.34 ms (2.27, +3%); 5,000 8.38 (8.24, +2%); 20,000 23.99 (24.7, -3%); 50,000 61.01 (61.6, -1%); 100,000 state updates 22.77 (25.2, -10%); 600 patcher cycles 308.94 (309.5, -0.2%); final AST VALID. All within 25%. `npm run build` passes (type check clean, JS bundle 37.50 KB / 13.10 KB gzip; `dist` restored afterwards). Note: inside an Orchestra task the composer sets `FRIED_FRICTION_LOG`, and with it set the benchmark's 600 patcher cycles each log a line: the first three benchmark runs measured 544-558 ms (+76%) and wrote ~1,800 non-friction lines to the task's harvest log (deleted before harvest; reported with `fried_friction`). Gate runs must unset it.
- consumers migrated: to be done by the master after merge. Orchestra dashboard: sync FriedJS 0.3.0 into `dashboard/vendor`, then replace `compile`/`parseQuery`/`match` in its `dashboard/lib/routes.js` with `matchRoute` (or `router`) over a route table built from its pages, keeping its own Dash-tab default as the `"*"` view and its tab/title lookup keyed by `pattern`; its tests must pass. Brain UI: sync only (it does not import the router); its tests must pass. No consumer depended on the old `"*"` result for a query-string or trailing-slash path (the dashboard did its own matching).
