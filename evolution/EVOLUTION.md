# How FriedJS evolves

Every change to FriedJS goes around one loop, and leaves an entry here.

1. **Friction.** An AI session or person using FriedJS hits something in the way. They append a line to `evolution/friction.jsonl` (format in `evolution/README.md`).
2. **Digest.** Repeated or serious friction is grouped by op and goal into one concrete problem, with the lines that prove it.
3. **Plan.** A change is proposed against that evidence: additive by default. Changing or removing behaviour needs a deprecation entry in `docs/known-limitations.md` and a migration patch for every consumer.
4. **Gates.** It ships only when all pass: `npm test` (including `tests/docs-truth.test.js`), `node stress.js` and `node benchmark.js` within 25% of `evolution/baseline.md`, every consumer's tests, this entry, and a verification note in `docs/MERGE.md`.
5. **Sync.** The pinned FriedJS is copied into each consumer (`fried sync <consumer>`), its version recorded, its tests run, and rolled back on failure.
6. Evidence over taste: an entry without friction evidence is not a reason to change anything.

## Entry format

```
## <id>. <title>
- id: <number, never reused>
- date: <YYYY-MM-DD>
- friction evidence: <friction.jsonl lines, or the defect found, with exact paths/errors>
- change: <what changed, files touched>
- tests: <tests added or changed>
- gates run: <each gate and its result, numbers vs baseline.md>
- consumers migrated: <each consumer and how, or "none needed: no behaviour change">
```

## 3. fried-router matches :param routes and a query string (phase F3a)

- friction evidence: `evolution/friction.jsonl` line 1 (consumer `orchestra-dashboard`, agent `codex`, op `route matching`): want "Match parameter routes such as /musicians/:id and /plans/:id", tried "Used fried-router router() route table", error "fried-router matches exact paths only", workaround "Use its currentRoute and navigate state, with route pattern compilation/matching in dashboard/lib/routes.js". - change: `addons/fried-router.js` only (plus the version stamp). `router(routes)` resolves through the new `matchRoute(routes, path)`: (1) a key equal to the whole path, query included, exactly as before; (2) the key equal to the path without its query; (3) `:name` patterns compared segment by segment (no regex built from pattern text), most literal segments wins, ties by declaration order, trailing slash ignored, params URL-decoded and kept raw on a bad escape; (4) `"*"`. Behaviour difference, documented: a path that used to fall to `"*"` only because of a query string or a trailing slash now reaches its route. Version 0.3.0 (`fried.js` `VERSION`, `package.json`, `CHANGELOG.md`, which also ships the F2 tooling that was under Unreleased). Docs: `docs/framework-api.md` (router section, both exports, example), `docs/known-limitations.md` (entry marked FIXED in 0.3.0), the router lines in `CLAUDE.md` and `README.md`, the 0.3.0 note in `docs/MERGE.md`.
